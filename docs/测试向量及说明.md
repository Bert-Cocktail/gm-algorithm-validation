# 测试向量及说明

本文档对应 `gm-algorithm-validation/vectors` 目录中的当前测试向量。它们是用于自动验证输入、输出和异常情况的 JSON 数据，不是生产环境密钥或真实业务数据。

## 总览

当前共有 6 个向量文件、64 个测试用例：

| 文件 | 算法/实验 | 用例数 | 主要用途 |
|---|---|---:|---|
| `sm3.json` | SM3 | 15 | 验证摘要计算和边界长度 |
| `hmac-sm3.json` | HMAC-SM3 | 4 | 验证带密钥的消息认证码 |
| `sm4.json` | SM4 | 28 | 验证 ECB、CBC、CTR 加解密 |
| `sm4-ctr-hmac-sm3.json` | SM4-CTR + HMAC-SM3 | 6 | 验证加密后认证、验签和篡改检测 |
| `sm2.json` | SM2 签名 | 6 | 验证签名和验签，包括错误签名 |
| `sm2-encryption.json` | SM2 加密 | 5 | 验证公钥加密、私钥解密和密文格式 |

## 各文件说明

### `sm3.json`

包含 15 个摘要向量（`tcId` 1--15）。覆盖空消息、`abc`、常见短消息、不同长度消息以及边界长度消息。输入通常是十六进制字符串 `message`，预期输出是十六进制摘要 `digest`。SM3 摘要固定为 32 字节，即 64 个十六进制字符。

### `hmac-sm3.json`

包含 4 个 HMAC-SM3 向量。每个用例提供 `key`、`message` 和预期 `mac`，用于检查密钥参与计算的认证结果。测试同时覆盖普通消息、空消息或较长输入等情况。HMAC-SM3 输出同样为 32 字节。

### `sm4.json`

包含 28 个 SM4 分组密码向量，分为 6 组：

- ECB 加密：`tcId` 1、5、11；ECB 解密：2、6、12。
- CBC 加密：3、7、13；CBC 解密：4、8、14。
- CTR 加密：9、15、17、19、21、23、25、27；CTR 解密：10、16、18、20、22、24、26、28。

常见字段有 `key`（16 字节密钥）、`iv`（CBC/CTR 使用的 16 字节初始值）、`plaintext`、`ciphertext`、`mode` 和 `direction`。ECB 不需要 IV；SM4 的分组和密钥长度均为 16 字节。

### `sm4-ctr-hmac-sm3.json`

包含 6 个认证加密向量。它先用 SM4-CTR 加密，再用 HMAC-SM3 计算认证标签；解密时先校验标签，标签不匹配时应拒绝输出明文。字段通常包括 `encryptionKey`、`macKey`、`iv`、`plaintext`、`ciphertext` 和 `tag`，其中 `tag` 用于检测密文或附加数据是否被修改。

### `sm2.json`

包含 6 个 SM2 签名验签向量，使用 `sm2p256v1` 曲线。前 5 个用例使用默认测试公钥和用户身份 `userId`，覆盖正确签名、修改消息、修改签名参数等情况；第 6 个使用派生的测试公钥。常见字段包括 `publicKey`、`userId`、`message`、`r`、`s` 和 `expected`。`expected` 表示验签应接受（`true`）还是拒绝（`false`）。

### `sm2-encryption.json`

包含 5 个 SM2 公钥加密向量，同样使用 `sm2p256v1` 曲线。用例 1--3 关注加密、解密和 C3 完整性检查；用例 4--5 关注密文格式转换或解密路径。常见字段有 `publicKey`、`privateKey`、`plaintext`、`ciphertext`、`format` 和 `expected`。SM2 密文可能表示为 DER、C1C3C2 或 C1C2C3，格式转换不应改变最终明文。

## JSON 字段速查

- `algorithm`：向量所属算法或组合实验。
- `description`：文件用途说明。
- `testGroups`：按曲线、模式、方向或签名格式划分的测试组。
- `tcId`：测试用例编号，便于定位失败项。
- `key` / `encryptionKey` / `macKey`：密钥，通常以十六进制表示。
- `iv`：初始化向量，适用于 CBC、CTR 或认证加密。
- `message` / `plaintext` / `ciphertext`：输入消息、明文和密文。
- `digest` / `mac` / `tag`：预期摘要、HMAC 或认证标签。
- `expected`：期望结果，常用于验签、解密或篡改检测。
- `source`：说明向量是标准向量、派生向量还是本地实验向量。

## 如何运行

在仓库根目录执行：

```powershell
python runner.py --all
```

也可以只运行某个文件，例如：

```powershell
python runner.py --vectors vectors/sm4.json
```

运行器会逐个读取 `tcId`，执行对应算法并报告通过或失败。向量用于学习、回归测试和后端交叉验证；固定测试密钥、私钥和随机数不得直接用于真实业务。
